## 기준 문서와 수치 우선순위

- 논문에 실제 포함된 주장·표·그림: `../paper_final.pdf`(2026-07-23 제출본)를 기준으로 정리했다.
- Note의 기존 학습 구조: `../KIISE-DBR_2026_Note.pdf`(24쪽)를 반영했다.
- 제출 이후 확인된 해석 경계·용어 보정: `../canonical/` 문서를 참조하되, 제출본 내용과 섞지 않고 `제출 이후 검증 메모`로 표시했다.
- 서로 충돌하는 수치는 제출본을 우선하고, 실제 원자산 재검증이 필요한 경우에는 단정하지 않는다.

## Notion 업로드 방법

- 통합 페이지가 목적이면 `00_KIISE_DBR_2026_NOTION_MASTER.md`와 `assets/`를 함께 보관한다.
- 절별 페이지가 목적이면 `01`–`12` 문서를 한 번에 가져온 뒤 번호 순서로 정렬한다.
- 수식은 Notion의 블록 수식으로 변환하기 쉽도록 `$$ ... $$` 형식을 사용했다.
- 표 안의 수치는 반올림된 제출본 수치다. 정밀 재분석에는 `../canonical/experiments/`의 원자산 계약을 사용한다.

## 원문 포함 방식

- 각 `01`–`12` 문서 마지막에 `논문 원문` 절을 추가했다.
- 원문은 `paper_final.pdf`의 해당 페이지를 150dpi 이미지로 직접 렌더링한 것이다. 문장을 다시 입력하지 않아 2단 편집, 표, 그림과 수치가 제출본 그대로 유지된다.
- 절 경계가 같은 PDF 페이지 중간에 있는 경우 인접 절의 일부가 함께 보인다. 각 부록의 설명에 이 중첩 범위를 명시했다.
- 원문 페이지 자산은 `assets/original_pages/page-01.jpg`부터 `page-21.jpg`까지다.
- 각 부록에는 원본 PDF의 해당 페이지를 여는 상대 링크도 포함했다.
- Notion에는 상위 경로의 `KIISE_DBR_2026_Notion_Import.zip`을 가져오면 Markdown과 원문 이미지가 함께 업로드된다.
- 통합본은 원문 21쪽 전체를 한 페이지에 포함하므로 매우 길다. Notion에서 빠르게 이동하려면 `01`–`12` 분할본을 우선 사용한다.
