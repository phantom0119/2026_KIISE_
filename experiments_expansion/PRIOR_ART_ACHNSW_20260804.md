# AC-HNSW 사전 문헌 검증 (Prior-Art Survey) — 2026-08-04

목적: KIISE-DBR RQ5(실측 상관 조건에서 전역 색인 재현율 손실 최대 0.627)를 SIGMOD/VLDB/ICDE급 알고리즘 논문(AC-HNSW)으로 확장하는 주제의 타당성 검증.
방법: 6개 각도 병렬 문헌 스윕(2022–2026 상위 학회+arXiv) + 완전성 비평 + 고위협 7편 원문 검증. 총 77편 정리.

## 고위협 논문 원문 검증 결과 (7편)

### ACORN: Performant and Predicate-Agnostic Search Over Vector Embeddings and Structured Data
- 존재확인: True | SIGMOD 2024 — Proceedings of the ACM on Management of Data (PACMMOD), Vol. 2, No. 3, Article 120, DOI 10.1145/3654923 (2024)
- C1(밀도 라우팅) 영역 침범: False | C2(예산 부분색인) 영역 침범: False | 비디오/시공간: False
- 판정: ACORN is the closest prior work to AC-HNSW's problem framing rather than its mechanisms: Section 3.2.1 formally defines predicate-embedding query correlation and empirically shows post-filtering collapsing under negative correlation (28-100x QPS gaps at 0.9 recall), which directly anticipates the proposal's motivating cluster-trap finding, so the claimed 62.7% recall loss must be demonstrated on ACORN itself under spatiotemporally clustered predicates to survive review, since ACORN claims consistent performance across correlation regimes. Mechanistically ACORN is deliberately predicate-AGNOSTIC: one global index with uniform M*gamma neighbor expansion (gamma fixed at construction by minimum workload selectivity, not runtime density) and two-hop filtered subgraph traversal, with no correlation- or diversity-aware edge allocation, entry-point adaptation, or per-predicate routing, leaving contribution 1 territory open. It likewise never materializes or destroys predicate-specific partial indexes under a workload-driven memory/latency budget, so contribution 2 (online MAV-style partial indexing) is untouched. Evaluation is image/text (SIFT1M, Paper, TripClick, LAION), not video/CCTV/spatiotemporal; net risk is motivational overlap (correlation formalism and robustness claim), and ACORN is a mandatory baseline whose correlation definition should be reused and stress-tested.
- 핵심 수치: 2-1,000x higher QPS at fixed recall vs prior methods overall; 28-100x higher QPS at 0.9 recall than next-best baseline on correlated (incl. negative-correlation) workloads where post-filtering fails to reach high recall; 30-50x QPS on TripClick/LAION-1M, >1,000x on LAION-25M; memory at most 1.3x HNSW; ACORN-gamma build time at most 11x HNSW; ACORN-1 gives 9-53x lower build time at up to 5x lower QPS.

### RACORN-1: Adaptive Recall-Preserving Speedup for Low-Selectivity Filtered Vector Search
- 존재확인: True | arXiv preprint (cs.DB, cs.IR) (2026)
- C1(밀도 라우팅) 영역 침범: True | C2(예산 부분색인) 영역 침범: False | 비디오/시공간: False
- 판정: RACORN-1 directly publishes the proposal's motivating phenomenon: it shows ACORN-1 recall collapsing to 0.08-0.41 under negatively correlated K-means cluster predicates at sub-1% selectivity, weakening AC-HNSW's novelty claim for the 62.7%-recall-loss finding itself. Its fix is query-time-only adaptive traversal — Adaptive Search Fallback repurposes filter-failing nodes as transient bridges and Adaptive Exact Fallback switches to linear scan when the running predicate-pass ratio drops — so it adapts traversal to observed selectivity/local predicate density (overlapping contribution 1's goal of escaping metadata-homogeneous clusters) but never modifies entry-point selection or edge allocation and does not estimate predicate-embedding correlation or a spatial-density weight, leaving AC-HNSW's index-side routing design formally distinct. It does nothing in contribution 2's territory: the paper explicitly positions itself as an in-place enhancement with zero extra memory and no partial-index materialization, and it excludes construction-time baselines (ACORN-gamma, Filtered-DiskANN) as out of scope. Evaluation uses SIFT/GIST/Text2Image with synthetic modulo predicates, not video/CCTV/spatiotemporal workloads, so AC-HNSW retains differentiation on edge/entry-point redesign, budgeted materialized partial indexes, and the video domain — but it must cite RACORN-1 and beat it as a baseline for the cluster-trap problem.
- 핵심 수치: Under negatively correlated K-means cluster predicates ACORN-1 recall collapses to 0.08-0.41; RACORN-1 restores 0.80-0.98 with 5-9x speedup vs HNSW. At 0.3% selectivity recall improves +0.74 to +0.88 (0.03-0.10 -> 0.77-0.98). 9-26x latency reduction vs HNSW in the 1%-0.3% selectivity sweet spot; RACORN-1+ reaches 20-75x at 0.1% selectivity with recall 1.00 (13x at 0.01% on 40M vectors). Zero additional memory and zero build-time overhead (in-place on existing HNSW).

### SIEVE: Effective Filtered Vector Search with Collection of Indexes
- 존재확인: True | PVLDB 18(11), pp. 4723-4736 (VLDB 2025) (2025)
- C1(밀도 라우팅) 영역 침범: False | C2(예산 부분색인) 영역 침범: True | 비디오/시공간: False
- 판정: SIEVE occupies most of AC-HNSW's Contribution 2: it materializes a workload-driven collection of predicate-specific sub-indexes under an explicit memory budget (Problem SIEVE-Opt constrains total sub-index size to budget B), using a three-dimensional size/search-time/recall analytical model to jointly select and parameterize them, so "budgeted partial vector indexes driven by observed workload" is already published at VLDB 2025. The genuine residual delta for Contribution 2 is only the online lifecycle: SIEVE adapts to workload shifts by re-running its offline selection (18ms optimization plus full ~136s rebuild) rather than incrementally creating/destroying sub-indexes during serving under a latency budget, and it does not handle a MAV-style online policy. Contribution 1 remains open against SIEVE: each sub-index is a standard HNSW with result-set filtering ("without specialized graph construction"), entry points and edges are never adapted to predicate density or metadata diversity, and predicate-embedding correlation appears only as a simplifying uniform term in its cost model. SIEVE also has no video/CCTV/spatiotemporal focus (YFCC, UQV, big-ann-style benchmarks), so the spatiotemporally-skewed workload framing is untouched, but any AC-HNSW submission must cite SIEVE and compare against it as the closest budgeted-collection baseline.
- 핵심 수치: Up to 8.06x speedup; less than 2.15x memory of a single standard HNSW; build time as low as 1% of other filtered indexes; SIEVE-Opt selection solved in 18ms vs 136s to build the index collection (YFCC).

### JAG: Joint Attribute Graphs for Filtered Nearest Neighbor Search
- 존재확인: True | arXiv preprint (cs.IR, cs.DB), arXiv:2602.10258; no peer-reviewed venue listed (2026)
- C1(밀도 라우팅) 영역 침범: True | C2(예산 부분색인) 영역 침범: False | 비디오/시공간: False
- 판정: JAG directly attacks the same failure mode motivating AC-HNSW's Contribution 1: it introduces attribute and filter distances that "transform binary filter constraints into continuous navigational guidance" and builds a proximity graph "jointly optimizing for both vector similarity and attribute proximity" explicitly to prevent navigational dead-ends where the predicate fails, with a threshold hierarchy of edges (JointRobustPrune degree-budget partitioning) targeting the whole selectivity spectrum — so metadata-aware edge construction against trapped filtered traversal is already occupied. However, JAG's attribute distance is baked in at build time as a static index with a fixed entry point; it does no runtime predicate-density estimation and no adaptive entry-point selection, leaving AC-HNSW's runtime density-estimation and entry-point angle as a narrower delta rather than a new problem. JAG has zero overlap with Contribution 2: there is no workload observation, no budget, and no dynamic creation/destruction of predicate-specific partial indexes — it is explicitly "a single graph-based index" with multiple navigational layers. It is also not video/spatiotemporal (datasets are SIFT, ARXIV, LAION, YFCC, MSTuring with Label/Range/Subset/Boolean filters), so the CCTV spatiotemporal-skew framing and the online materialized-partial-index contribution remain differentiated, but AC-HNSW must cite JAG as close prior art for C1 and be compared against it.
- 핵심 수치: Up to 10x higher QPS at recall 0.9 vs second-best filter-agnostic baseline on LAION-25M/YFCC mixed workloads; QPS >10,000 at recall 0.8 on MSTuring-10M range filters where filter-agnostic algorithms need QPS <50 to reach 0.8 recall; first graph-based method to exceed 0.95 recall at QPS >50 on YFCC highly-selective (<1%) subset queries. Baselines include ACORN, NaviX, FilteredVamana/StitchedVamana, NHQ, UNG, iRangeGraph across 5 datasets.

### iRangeGraph: Improvising Range-dedicated Graphs for Range-filtering Nearest Neighbor Search
- 존재확인: True | SIGMOD 2025 (Proc. ACM Manag. Data / PACMMOD; camera-ready header "SIGMOD '25, June 22-27, 2025, Berlin") (2025)
- C1(밀도 라우팅) 영역 침범: False | C2(예산 부분색인) 영역 침범: False | 비디오/시공간: False
- 판정: iRangeGraph directly undercuts the proposal's contribution-2 premise for temporal (1D numeric range) predicates: it shows per-range dedicated graph indexes need not blow up space or build cost, because offline "elemental graphs" over a segment-tree (O(nm log n) space) let it compose a dedicated graph for ANY query range on the fly with provably low overhead and stable performance across workloads — all without workload observation. However, strictly it does neither claimed contribution: materialization is fixed and offline with no workload-driven budget policy or create/destroy lifecycle (the per-query composed graph is ephemeral, not a managed materialized view), and traversal on the composed graph is standard greedy/beam search with no adaptation of entry points or edge allocation to predicate-embedding correlation or metadata density. Its Section-4 extension to conjunctive multi-attribute numeric range predicates also covers part of the spatiotemporal predicate space (time ranges, numeric coordinates), though categorical predicates like camera ID are out of scope. AC-HNSW must therefore position against it explicitly: novelty survives mainly for categorical/arbitrary predicates, correlation/density-aware routing, and online budgeted adaptation, and iRangeGraph is a mandatory baseline for any temporal-range experiments.
- 핵심 수치: 2x-5x QPS over the most competitive baseline at 0.9 recall for RFANN with consistently smaller memory footprint; 2x-4x QPS at 0.9 recall for the multi-attribute extension; within <2x of ideal per-range dedicated-graph performance at 0.9 recall; space O(nm log n) vs O(n^3 m) for full dedicated-index materialization; prior compressed-index approach cannot achieve >0.8 recall on short ranges.

### CubeGraph: Efficient Retrieval-Augmented Generation for Spatial and Temporal Data
- 존재확인: True | arXiv preprint (cs.DB), arXiv:2604.06616, formatted for/targeting PVLDB (placeholder volume info); not yet a verified accepted-venue publication (2026)
- C1(밀도 라우팅) 영역 침범: True | C2(예산 부분색인) 영역 침범: False | 비디오/시공간: True
- 판정: CubeGraph targets exactly AC-HNSW's predicate class (vector similarity + location/time filters) and the same failure mode (graph fragmentation and connectivity loss under spatial predicates), solving it with per-cell partial HNSW graphs plus query-time stitching of filter-intersecting cubes into one connected traversal — so it directly occupies the "global index vs per-predicate partial index" gap the proposal claims is unfilled, and it even evaluates clustered/skewed metadata distributions. Its routing adaptation is real but purely metadata-geometric: grid layer chosen by filter characteristic length (selectivity), entry points seeded from filter-intersecting cubes, and per-query gating of statically built cross-cube edges — it never estimates predicate-embedding correlation or embedding-space density and has no diversity-weighted edge allocation, so C1's specific mechanism (and the 62.7% correlation-induced recall-loss phenomenon, since its synthetic attributes are independent of embeddings) remains open. It has no workload-driven budgeted materialization: all per-cube indexes at all layers are built offline with roughly 6x memory blow-up over plain HNSW, and adaptive partitioning for skew is explicitly future work, which actually strengthens the motivation for C2's online MAV-style policy. AC-HNSW must cite CubeGraph as the closest prior art, add it (not just ACORN/pgvector) as a baseline, and reposition C1 around embedding-metadata correlation and true video/CCTV embeddings, which CubeGraph does not evaluate.
- 핵심 수치: Up to 5,730 Qps at 92% recall on SIFT (72x vs ACORN-gamma, 21x vs PostFiltering); MSMARCO10M 144 Qps at 99%+ recall vs PostFiltering 15 Qps (ACORN capped at 88% recall); YFCC 100x speedup vs PostFiltering (ACORN saturates at 24% recall); Deep100M (100M vectors) 99.5% recall at 250 Qps, ~5h build; skewed metadata 2.5x faster than uniform but clustered metadata halves Qps at filter ratio 0.1; index size ~6x plain HNSW (SIFT 1038MB vs 172MB) since every point is replicated across L grid layers; incremental updates 2.6-8.5x faster than rebuild.

### NaviX: A Native Vector Index Design for Graph DBMSs With Robust Predicate-Agnostic Search Performance
- 존재확인: True | PVLDB Vol. 18, No. 11, pp. 4438-4450 (VLDB 2025); also arXiv:2506.23397 (2025)
- C1(밀도 라우팅) 영역 침범: True | C2(예산 부분색인) 영역 침범: False | 비디오/시공간: False
- 판정: NaviX sits squarely in AC-HNSW contribution-1 territory: it estimates the LOCAL selectivity of the predicate around each candidate vector (fraction of the candidate's HNSW neighbors in the prefiltered subset S) and adaptively switches expansion heuristics (onehop-s/directed/blind) at every kNN iteration, explicitly to stay robust under correlated ad-hoc predicates — the same cluster-trapping failure mode motivating AC-HNSW's 62.7% recall-loss claim. However, its adaptation is purely query-time traversal strategy on an unmodified global HNSW: it does not alter edge construction/allocation, add metadata-diversity edge weights, or change entry-point selection, which are the parts of contribution 1 that remain novel-ish but must now be positioned against (and shown to beat) NaviX's adaptive-local mechanism. It has zero overlap with contribution 2 — it maintains a single global index with prefiltering and never materializes/destroys workload-driven partial indexes under a memory/latency budget. It is implemented in the Kuzu graph DBMS on text/image/Wikipedia-KG embeddings with no video/CCTV/spatiotemporal angle, so AC-HNSW's domain framing survives, but NaviX is a mandatory baseline and a direct threat to a naive version of contribution 1.
- 핵심 수치: Wiki dataset 15.4M vectors: NaviX index build 55.22 min vs Milvus 182.42 min; adaptive-local heuristic reported to outperform any single fixed heuristic, especially under predicate-embedding correlation; evaluated against ACORN, Weaviate 1.28.2, Milvus 2.5.0, DiskANN/Filtered-DiskANN, iRangeGraph, PGVectorScale, VBase across varying selectivities.

## 각도별 결론

### [graph-filtered-ann]
The claimed gap is real only in a much narrower form than stated. Predicate-embedding correlation is NOT unstudied: ACORN (SIGMOD 2024) formally defines positive/negative query correlation with clustered predicates and evaluates under it (claiming robustness, which the proposal's 62.7%-loss finding must directly rebut), and the RACORN-1 preprint (2026) already documents ACORN-1 recall collapse under K-means-cluster-correlated filters and repairs it with adaptive traversal; predicate-aware entry-point selection and label-aware edge construction are likewise established (Filtered-DiskANN, UNG, JAG) and are even dissected component-by-component in a SIGMOD 2026 experimental study. For contribution 2, SIEVE (VLDB 2025) already does budgeted, workload-aware collections of predicate-specific indexes with a size/time/recall cost model, HONEYBEE (SIGMOD 2026) does constrained-optimization partition materialization, and SeRF/iRangeGraph neutralize the 'partial indexes blow up' premise for ordered (time-range) attributes. What remains defensibly open: (a) runtime predicate-density estimation driving DIVERSITY-WEIGHTED edge allocation and entry-point adaptation (vs ACORN's static predicate-agnostic expansion and RACORN's fallback bridges), (b) a truly ONLINE create/destroy materialized-partial-index policy under joint latency+memory budgets (vs SIEVE/HONEYBEE's offline selection), and (c) the spatiotemporal CCTV/video instantiation — but each must be framed as a delta over these systems, several of which (SIEVE, RACORN-1, JAG, the SIGMOD 2026 study) are 2025-2026 work the proposal does not yet cite.

### [range-temporal-ann]
For this angle the claimed gap is real only in a narrow slice and is otherwise overstated. (1) Pure temporal/range predicates are a saturated subfield: SeRF, beta-WST, iRangeGraph, DIGRA, RangePQ, the VLDB'25 dynamic segment graph, WoW, and UDG collectively give static, dynamic, and streaming range-filtered ANN at near-single-index build cost, so the motivating strawman that 'partial indexes blow up size and offline rebuild cost' is already false for time windows — iRangeGraph in particular materializes cheap elemental graphs composable into an index for ANY range, and any SIGMOD/VLDB reviewer will demand these as baselines, not just ACORN/Milvus/pgvector. (2) Contribution 2 (budgeted dynamic materialized partial indexing) is substantially anticipated by SIEVE (VLDB 2025), which already does workload-aware, memory-budgeted collections of predicate-dedicated indexes with query routing; the surviving delta is only the online create/destroy MAV-style policy, and for the temporal axis even that is squeezed by incremental designs like WoW/DIGRA. (3) The genuinely open slice is joint 2D-location + time predicates, but concurrent 2026 work is already moving there: CubeGraph explicitly serves spatio-temporal hybrid filters via per-grid-cell vector graphs stitched at query time, and KHI handles multi-attribute range boxes with skew-aware partitioning — so 'first spatiotemporal filtered ANN index' is not claimable. (4) Contribution 1 (runtime predicate-density estimation driving entry-point selection and diversity-weighted edge allocation for metadata-clustered embeddings) remains the most defensible novelty within this angle — none of the surveyed range/temporal systems adapt graph routing to predicate-cluster correlation — but the correlation phenomenon itself is being formalized as a hardness dimension (HCBGen, PVLDB'26), so the 62.7% recall-loss analysis supports motivation rather than standing as a contribution. Streaming unfiltered systems (FreshDiskANN, SPFresh) remain low-threat since they carry no predicate support.

### [workload-budgeted-partial]
For claimed contribution 2 the gap as stated is not real: SIEVE (VLDB 2025) already delivers workload-aware packing of predicate-specific HNSW subindexes under an explicit memory budget, AND its own Sections 6/7.7 show the collection being incrementally updated online under workload shift — re-solving the optimizer, building new subindexes and deleting stale ones during serving, with cold-start and sub-second steady-state updates — so both the 'budgeted' and much of the 'dynamic' halves of Budgeted Dynamic Materialized Partial Indexing are taken, and SIEVE even shares the ACORN baselines. HoneyBee (SIGMOD 2026) occupies the adjacent budget-constrained overlapping-partition optimization space (MINLP over memory/latency/recall) for RBAC predicates, Quake (OSDI 2025) owns cost-model-driven online index adaptation to skewed workloads, and shipped systems (Weaviate tenant offloading, Turbopuffer namespace caching) already do heuristic per-predicate index lifecycle management under memory pressure. What genuinely remains open: an explicit joint latency-SLA + memory dual-budget admission/eviction policy framed as materialized-view management with continuous (not slice-batched) adaptation; exploiting predicate-embedding correlation (the proposal's contribution-1 signal) to choose WHICH partial indexes to materialize; support for correlated spatiotemporal (location x time-range) predicates rather than SIEVE's categorical filter templates; and video/CCTV-scale evaluation. Contribution 2 is publishable only if repositioned as a measured increment over SIEVE — which must be cited and run as a baseline — not as the first workload-aware budgeted partial-index manager for vector search.

### [correlation-skew-analysis]
The motivating mechanism is real but no longer unclaimed territory: RACORN-1 (arXiv 2607.00768, July 2026) already constructs the exact adversarial regime AC-HNSW motivates — filters aligned with K-means embedding clusters causing near-total recall collapse in ACORN-1/HNSW — and ships a runtime fix (transient bridge nodes plus exact fallback), while ACORN itself (SIGMOD 2024) ran correlated-predicate experiments and claims predicate-agnostic robustness, so the "62.7% recall loss" story must be shown to break ACORN-gamma (not just ACORN-1) and to survive alpha-Hardness-style scrutiny, since the HCBGen paper shows raw attribute-vector correlation is an unstable hardness proxy and the GLS metric paper already formalizes filter-vector correlation measurement. On contribution 1, the specific combination of runtime predicate-density estimation with diversity-weighted edge allocation is not exactly taken, but its two halves are heavily grazed: JAG and NHQ already make graph edges/navigation attribute-aware to prevent predicate-region trapping, and the Hub-Highway paper undercuts the value of adaptive entry-point selection in high dimensions. What remains genuinely open in this angle: a spatiotemporal/video-specific characterization of cluster-aligned CCTV predicates (no paper found does this), a principled runtime (not construction-time) density-aware routing policy benchmarked against JAG/RACORN-1, and the coupling to budgeted online partial-index materialization — contribution 2 is untouched by the correlation-analysis literature surveyed here, though adjacent multi-tenant partitioning work (Curator, HONEYBEE SIGMOD 2026) should be checked by the partial-index sweep.

### [video-spatiotemporal-systems]
For the video/multimodal/geospatial angle, the narrow gap — an ANN index co-designed for spatiotemporal CCTV metadata predicates that correlate with embedding clusters — is still real for CCTV video specifically, but the surrounding space is closing fast and the proposal's "existing options fail" framing is already partially stale. Video DBMSs and video-RAG systems (Seiden, Zelda/VIVA, EVA, TASTI, iRAG) all operate at pipeline/optimizer level and never touch the index, which supports the gap; however, at the index level CubeGraph (arXiv Apr 2026) already delivers a spatial-partitioned modular vector-graph index with dynamic cell stitching that plausibly refutes the claimed global-vs-partial-index dichotomy for spatial predicates, and Milvus 2.6.4 (Mar 2026) now ships native GEOMETRY+R-Tree hybrid search, so the Milvus baseline claim must be re-verified against it. Contribution 1's specific mechanism (metadata-diversity-weighted edge allocation and density-aware entry points) appears unclaimed in this angle — RACORN-1 adapts traversal under clustered low-selectivity predicates but via bridge/fallback, and SpatCode instead fuses space-time into the embedding — while contribution 2's workload-driven budgeted create/destroy of partial indexes as online materialized views also appears open, with CubeGraph (static grid cells) and EVA (UDF-result MVs) as the nearest neighbors that must be cited and differentiated. Also note older spatial-visual hybrid index prior art (Alfarrarjeh & Shahabi 2017; GeoVideoIndex 2017 for pre-embedding georeferenced video), which forecloses any "first spatial-visual hybrid index" claim even though it predates HNSW-era filtered ANN.

### [latest-2025-2026]
The 2025-2026 literature substantially narrows both claimed gaps, and the proposal's related-work framing ("global indexes vs. static pgvector partial indexes are the only options") is already false as stated. Contribution 2's core — budget-constrained collections of predicate-specific partial vector indexes selected from workload knowledge — is largely delivered by SIEVE (VLDB 2025: workload-aware, memory-budgeted index packing plus model-based query-time routing), with PathFinder adding cost-based multi-index routing and CrackIVF/Quake establishing online, workload-driven index construction/restructuring; the only surviving delta is a genuinely ONLINE create/destroy policy (MAV-style, joint latency+memory budgets, workload drift), which no found paper does for predicate-specific vector indexes. Contribution 1's runtime "predicate density" adaptation is closely anticipated by NaviX (VLDB 2025: per-iteration local-selectivity-adaptive traversal under arbitrary correlated predicates), while RWalks and the ICML-workshop filter-aware-metric paper already put attribute information into graph edges; a metadata-DIVERSITY-weighted edge budget with density-aware entry-point selection is not exactly published, but it must now be positioned as an increment over NaviX/RWalks, not as the first filter-aware traversal fix. The motivating phenomenon (recall collapse when predicates correlate with embedding clusters) is well documented since ACORN and re-quantified by RACORN-1 and the VLDB 2026 hardness benchmark, so the 62.7% CCTV finding is corroborating evidence, not a new discovery. The clearest remaining open ground is the domain instantiation: no 2025-2026 DB-venue paper targets spatiotemporally skewed multimodal VIDEO embeddings with filtered ANN (SpatCode is the nearest and takes an encoding, not indexing, route) — so the paper survives only if it leads with the online-materialization-policy delta vs. SIEVE and the diversity-weighted edge allocation vs. NaviX, evaluated on the CCTV workload.

## 완전성 비평 (critic)

The sweep is strong on 2024-2026 DB-venue papers but missed an entire production layer that directly grazes contribution 1: Qdrant has shipped payload-aware extra HNSW edges (predicate-aware edge allocation) for years and now adds an ACORN mode, Weaviate's ACORN implementation ships random entry-point seeding into the filtered zone, Lucene/Elasticsearch/Solr adopted ACORN-1 as the default filtered path, OpenSearch ships a threshold-based adaptive exact-search fallback, and pgvector 0.8 iterative scans repair the very recall failure the proposal's strawman rests on — so both halves of contribution 1 (entry-point adaptation, metadata-aware edges) exist in degraded-but-shipped form, and the proposed baselines (research-code ACORN + Milvus + pgvector partial) are a generation stale. The most threatening missing academic items are Curator SIGMOD 2026 (per-label adaptive partial indexes in a shared clustering tree, motivated by the same connectivity-breakdown pathology; joins SIEVE/HONEYBEE against contribution 2), DEG SIGMOD 2025 (query-adaptive edge activation, the nearest published relative of diversity-weighted edge allocation), plus VBASE, ARKGraph, UNIFY, VecFlow, the VLDB 2025 filtered-vector-search tutorial, and three uncited benchmark instruments (Big-ANN NeurIPS'23 filter track, VecBench SIGMOD 2026, ETH FANNS benchmark) that the 62.7% finding and the evaluation must be positioned against. Still-uncovered modalities: Chinese-language venues and industry blogs (Journal of Software/JCST, Alibaba Proxima, Tencent VectorDB, Vearch — structurally invisible to the US-only search used here and in the sweep), patents, competition/benchmark repos beyond what I probed, CV/multimedia venues (TRECVID, ACM MM moment-retrieval-with-metadata), and the pre-embedding CCTV forensic metadata-querying literature (e.g., 'Spatio-Temporal Metadata Querying for CCTV Video Retrieval', 2018), which forecloses any 'first spatiotemporal CCTV query' rhetoric even though it supports the vector-index-level gap. Summary errors to fix: the 'deduped' list still contains two duplicate pairs — the SIGMOD 2026 attribute-filtering study appears twice with contradictory threat ratings and contradictory claims about whether it centers correlation (one entry is a guess), and HCBGen appears twice (PVLDB 19(10) and arXiv) — while OOD-DiskANN's 'ACM Web Conference 2023' venue looks conflated with Filtered-DiskANN (I can only verify it as an arXiv preprint), the 'Down with the Hierarchy' ECIR 2026 venue is unverified and its hub-based argument targets the value of the hierarchy on unfiltered search rather than predicate-region entry points (so it is a weaker counter to contribution 1 than the sweep claims), and the Weaviate entry describes multi-tenancy only, missing Weaviate's ACORN filtered search. Net: the two claimed contributions survive only as narrow deltas — correlation-driven runtime density estimation feeding both edge allocation (vs Qdrant/DEG/JAG) and an online create/destroy partial-index policy (vs SIEVE/Curator/HONEYBEE) — and the paper must add a 'shipped systems' related-work subsection and refresh its baselines to 2025-2026 production implementations to be credible at SIGMOD/VLDB/ICDE.

### 논문별 한 줄 요약

- **ACORN: Performant and Predicate-Agnostic Search Over Vector Embeddings and Structured Data** (SIGMOD 2024 (PACMMOD)): Modifies HNSW with predicate-agnostic neighbor expansion (M·gamma candidate lists sized by minimum selectivity, two-hop expansion instead of RNG pruning) and filtered greedy traversal over the predicate subgraph. Crucially, it FORMALLY DEFINES query correlation between predicates and embedding clusters (positive/negative correlation, Sec 3.2.1), shows post-filtering collapses under negative correlation (28-100x gaps), and claims ACORN itself stays consistent across correlation conditions. [https://arxiv.org/abs/2403.04871]
- **RACORN-1: Adaptive Recall-Preserving Speedup for Low-Selectivity Filtered Vector Search** (arXiv 2026 (preprint)): Documents exactly the proposal's motivating phenomenon — ACORN-1 recall collapse (0.08-0.41) under NEGATIVELY CORRELATED K-means-cluster predicates and sub-1% selectivity — and fixes it with adaptive traversal: filter-failing nodes reused as temporary bridges (Adaptive Search Fallback) plus exact-scan fallback, restoring recall to 0.80-0.98. It is adaptive traversal rather than entry-point/edge-allocation redesign, but it already delivers a published fix for cluster-trapped filtered traversal. [https://arxiv.org/abs/2607.00768]
- **SIEVE: Effective Filtered Vector Search with Collection of Indexes** (VLDB 2025 (PVLDB 18(11))): Builds a workload-aware COLLECTION of predicate-specific sub-indexes under a memory budget, using a three-dimensional analytical model (index size / search time / recall) to jointly select and parameterize indexes; 8.06x speedup at <2.15x HNSW memory. This is most of claimed contribution 2 (budgeted predicate-specific partial indexes driven by observed workload); the remaining delta is only an ONLINE create/destroy policy versus SIEVE's selection for a historical workload. [https://arxiv.org/abs/2507.11907]
- **JAG: Joint Attribute Graphs for Filtered Nearest Neighbor Search** (arXiv 2026 (Feb; Blelloch/Dhulipala/Jayaram/Lacki)): Builds proximity graphs that jointly optimize vector similarity and attribute proximity, turning binary filters into continuous navigational guidance explicitly to prevent traversal getting trapped in regions where the predicate fails; evaluated on Label/Range/Subset/Boolean filters across five datasets. [https://arxiv.org/abs/2602.10258]
- **iRangeGraph: Improvising Range-dedicated Graphs for Range-filtering Nearest Neighbor Search** (SIGMOD 2025 (PACMMOD)): Materializes 'elemental graphs' over a segment tree (O(log n) layers) and composes a dedicated graph index for ANY query range on the fly at moderate space, with stable performance across workloads. This directly undercuts the proposal's premise that per-predicate partial indexes must blow up size/build cost — for 1D range (temporal) predicates that problem is essentially solved without workload adaptation. [https://arxiv.org/abs/2409.02571]
- **CubeGraph: Efficient Retrieval-Augmented Generation for Spatial and Temporal Data** (arXiv 2026 (2604.06616)): Explicitly targets hybrid queries combining vector similarity with SPATIO-TEMPORAL filters: hierarchical grid partitioning keeps an independent vector graph per spatial cell and dynamically stitches adjacent cube-level indexes into a unified single-pass traversal when the query's spatial/temporal filter overlaps them. This is the closest prior art to the proposal's exact predicate class (location + time) and already combines per-cell partial indexes with cross-partition graph traversal. [https://arxiv.org/abs/2604.06616]
- **NaviX: A Native Vector Index Design for Graph DBMSs With Robust Predicate-Agnostic Search Performance** (PVLDB Vol 18 / VLDB 2025): Prefiltering-based HNSW search inside a graph DBMS that estimates the LOCAL selectivity of the predicate around each vector at runtime and adaptively switches traversal/candidate-expansion heuristics at every iteration of the kNN search, explicitly to stay robust under arbitrary correlated ad-hoc predicates. [https://arxiv.org/abs/2506.23397]
- **Qdrant Filterable HNSW (payload-aware extra graph edges + ACORN search mode)** (Vendor system (Qdrant docs/articles; shipped for years, ACORN mode 2025)): Qdrant's core index builds ADDITIONAL HNSW edges per indexed payload-field value (per-value connected subgraphs merged into the main graph) so filtered traversal stays connected, and now layers an ACORN-1-style two-hop search on top for filter combinations the extra edges miss. This is shipped predicate-aware edge allocation — the edge-allocation half of contribution 1 exists in production and the proposal's baseline set omits it entirely. [https://qdrant.tech/articles/vector-search-filtering/]
- **Curator: Efficient Vector Search with Low-Selectivity Filters** (SIGMOD 2026 (arXiv 2601.01291; PACMMOD DOI 10.1145/3786635)): Documents graph 'connectivity breakdown' on low-selectivity filtered queries (the proposal's motivating pathology) and answers it with a partition-based index that builds specialized per-label indexes inside a shared clustering tree, each adapting to its qualifying-vector distribution. Adaptive per-predicate partial indexes sharing one budgeted structure — a direct hit on contribution 2's territory alongside SIEVE, from the same group as the 2024 multi-tenant Curator. [https://arxiv.org/abs/2601.01291]
- **DEG: Efficient Hybrid Vector Search Using the Dynamic Edge Navigation Graph** (SIGMOD 2025 (PACMMOD, DOI 10.1145/3709679; arXiv 2502.07343)): Builds a graph whose edges carry 'active ranges' so the edge set actually used adapts at query time to the query's attribute-vs-vector weight alpha (Pareto-frontier candidate selection + dynamic edge pruning + edge seeds). Query-adaptive edge activation for attribute-influenced search is thus already published — diversity-weighted edge allocation must be differentiated from DEG's mechanism. [https://arxiv.org/abs/2502.07343]
- **Filtered-DiskANN: Graph Algorithms for Approximate Nearest Neighbor Search with Filters** (WWW 2023): FilteredVamana/StitchedVamana build graph edges using BOTH vector geometry and label metadata, and search starts from label-specific entry points — so predicate-aware entry-point selection and label-aware edge construction already exist in the literature. Limited to equality labels and no explicit model of attribute-embedding correlation or diversity-weighted edges. [https://dl.acm.org/doi/10.1145/3543507.3583552]
- **Navigating Labels and Vectors: A Unified Approach to Filtered Approximate Nearest Neighbor Search (UNG)** (SIGMOD 2025 (PACMMOD)): Adds a Label Navigating Graph encoding label-set containment on top of Vamana, routing search entry through label-compatible regions with a fidelity guarantee (searches only filtered vectors); ~10x speedup at same accuracy. Predicate-aware entry routing is thus already published; no runtime density estimation or correlation-adaptive edge weighting. [https://dl.acm.org/doi/abs/10.1145/3698822]
- **Attribute Filtering in Approximate Nearest Neighbor Search: An In-depth Experimental Study** (SIGMOD 2026 (arXiv 2508.16263)): Benchmarks 12 filtered-ANN methods across 4 datasets and selectivities 0.1%-100%, with COMPONENT-LEVEL analysis of pruning, ENTRY-POINT SELECTION, and edge-filtering costs. A measurement paper that likely pre-empts much of the proposal's motivating recall-loss analysis; the 62.7%-loss finding must be positioned against it. [https://arxiv.org/abs/2508.16263]
- **HONEYBEE: Efficient Role-based Access Control for Vector Databases via Dynamic Partitioning** (SIGMOD 2026 (arXiv 2505.01538)): Formulates predicate(role)-specific overlapping partitions with strategic vector replication as a constrained optimization balancing memory, query efficiency, and recall — comparable performance to dedicated per-role indexes at 90.4% less extra memory. A budgeted partition/partial-index materialization scheme, though specialized to RBAC permission predicates and not an online create/destroy workload policy. [https://arxiv.org/abs/2505.01538]
- **SeRF: Segment Graph for Range-Filtering Approximate Nearest Neighbor Search** (SIGMOD 2024 (PACMMOD)): Losslessly compresses ALL n range-specific HNSW indexes into one segment graph at the build time/space of a single HNSW, enabling arbitrary range-filtered search (iRangeGraph, SIGMOD 2025, refines this with segment-tree range subgraphs). Directly undercuts the claim that per-predicate partial indexes must blow up size/build cost for ordered attributes like CCTV timestamps. [https://dl.acm.org/doi/10.1145/3639324]
- **An Efficient and Robust Framework for Approximate Nearest Neighbor Search with Attribute Constraint (NHQ)** (NeurIPS 2023): Native hybrid-query framework fusing attribute and vector distance into one composite proximity-graph index with optimized edge selection and routing, so traversal is guided by attribute agreement rather than post-filtering; up to 315x faster at equal accuracy on 10 datasets. [https://papers.nips.cc/paper_files/paper/2023/hash/32e41d6b0a51a63a9a90697da19d235d-Abstract-Conference.html]
- **Approximate Nearest Neighbor Search with Window Filters (beta-WST)** (ICML 2024): Defines c-approximate window search (numeric label ranges, e.g., timestamps) and gives a modular tree-based framework that turns any ANN index into a window-filtered one, with up to 75x speedup at equal recall, evaluated on image embeddings with real timestamps. Time-window predicates handled natively; single label dimension, static, no spatial or cluster-correlation handling. [https://arxiv.org/abs/2402.00943]
- **DIGRA: A Dynamic Graph Indexing for Approximate Nearest Neighbor Search with Range Filter** (SIGMOD 2025 (PACMMOD 3(3))): Dynamic range-filtered ANN: fuses a dynamic multi-way tree with localized proximity graphs so insertions/deletions and attribute-distribution shift are absorbed by the tree without fragmenting graph topology (attributes like timestamps/prices). Covers the dynamic+range axis the proposal needs for time predicates, but single-attribute and not workload/budget-driven. [https://dl.acm.org/doi/abs/10.1145/3725399]
- **Dynamic Range-Filtering Approximate Nearest Neighbor Search** (VLDB 2025 (PVLDB 18(10))): Peng, Qiao, Zhou, Li, Deng (the SeRF group) extend segment graphs to the fully dynamic setting where data vectors and range-filtered queries arrive in a mixed stream, supporting incremental construction with insertions/deletions. Closes the 'streaming + range filter' gap for one numeric attribute; no spatial dimension, no query-workload-adaptive materialization. [https://www.vldb.org/pvldb/vol18/p3256-deng.pdf]
- **WoW: A Window-to-Window Incremental Index for Range-Filtering Approximate Nearest Neighbor Search** (SIGMOD 2026 (PACMMOD; arXiv 2508.18617)): Incremental window-graph RFANNS index: inserts vector-attribute pairs into hierarchical window graphs of varying window size and optimizes relevant-window search by range selectivity for arbitrary range filters. Another incremental range-filter design occupying the temporal-predicate space; single attribute, selectivity-aware but not cluster-correlation-aware. [https://arxiv.org/abs/2508.18617]
- **Efficient Approximate Nearest Neighbor Search under Multi-Attribute Range Filter (KHI)** (arXiv 2026 (cs.DB, 2602.15488)): KHI handles RFANNS with ranges over MULTIPLE numeric attributes via an attribute-space partitioning tree with a skew-aware splitting rule (O(log n) height) plus HNSW graphs attached to tree nodes, with tree routing at query time. A spatiotemporal box (lat, lon, time) is exactly a multi-attribute range, so this concurrent work erodes the 'no index handles spatiotemporal predicates' framing, though it is not correlation/cluster-aware and not workload-adaptive. [https://arxiv.org/abs/2602.15488]
- **Revisiting Filtered ANN Benchmarks: A Hardness-Controlled Benchmark Generator for Realistic Evaluation (HCBGen)** (VLDB 2026 (PVLDB 19(10); arXiv 2606.14193)): Introduces alpha-Hardness, a query-level hardness metric for filtered ANN, and shows common proxies including ATTRIBUTE-VECTOR CORRELATION are unstable/strategy-inconsistent hardness signals, while existing benchmarks occupy a narrow easy regime that masks robustness gaps. Directly overlaps the proposal's correlation-analysis component: the phenomenon 'predicate-embedding correlation breaks filtered search' is already being formalized and benchmarked, so the 62.7% recall-loss finding must be positioned against this hardness framework rather than presented as a new discovery. [https://arxiv.org/abs/2606.14193]
- **High-Throughput Vector Similarity Search in Knowledge Graphs (HQI)** (SIGMOD 2023 (PACMMOD)): Apple's workload-aware hybrid index: tailors vector data partitioning layout to an observed hybrid (predicate+vector) query workload and adds multi-query optimization for batch filtered ANN, reporting 31x throughput gains. Partitioning is fit offline to the workload (static); no online creation/destruction or budgeted lifecycle, and it targets batch/offline query settings rather than online serving. [https://arxiv.org/abs/2304.01926]
- **Quake: Adaptive Indexing for Vector Search** (OSDI 2025): Adaptive multi-level partitioned index that reorganizes partitions online in response to updates and skewed/shifting access patterns, guided by a cost model predicting query latency from partition sizes and access frequencies, plus recall-target-driven query parameterization. Fully dynamic and workload-adaptive, but adapts one global index to access skew rather than materializing predicate-specific partial indexes for filtered search. [https://arxiv.org/abs/2506.03437]
- **Predicate Caching: Query-Driven Secondary Indexing for Cloud Data Warehouses** (SIGMOD Companion 2024 (Amazon Redshift)): Builds lightweight per-predicate secondary index entries (cached qualifying row ranges) on the fly from the live query workload and keeps them online without recomputation, behaving as a budgeted cache of predicate-specific access paths. Relational scans, not vector search, but it is direct prior art for the 'online, query-driven, cache/MAV-style materialization of predicate-specific access structures' policy idea in contribution 2. [https://dl.acm.org/doi/10.1145/3626246.3653395]
- **Weaviate multi-tenancy: per-tenant indexes, tenant states, and Tenant Controller** (Vendor system (Weaviate docs/blog)): Shipped system where each tenant (a partition-key predicate) gets its own shard with dedicated vector index; a Tenant Controller dynamically activates/deactivates/offloads per-tenant indexes across hot/warm/cold tiers based on usage to bound memory, and a 'dynamic index' upgrades flat to HNSW per tenant at size thresholds. This is a production equivalent of dynamically created/destroyed predicate-specific vector indexes under resource constraints, though only for the single tenant-key predicate and driven by activity heuristics rather than a latency/memory optimizer. [https://weaviate.io/developers/weaviate/starter-guides/managing-resources/tenant-states]
- **Revisiting Filtered ANN Benchmarks: A Hardness-Controlled Benchmark Generator for Realistic Evaluation** (arXiv 2026 (cs.DB, June)): Proposes a query-level alpha-Hardness metric for filtered ANN and the HCBGen generator that synthesizes workloads under controlled correlation/bias modes; shows selectivity and attribute-vector correlation are unstable proxies for hardness and that popular benchmarks occupy an easy slice of the hardness spectrum. [https://arxiv.org/pdf/2606.14193]
- **Filtered Approximate Nearest Neighbor Search in Vector Databases: System Design and Performance Analysis** (arXiv 2026 (cs.DB, Feb)): Systematizes filtering strategies and evaluates FAISS/Milvus/pgvector on a new metadata-rich dataset (MoReVec), introducing the Global-Local Selectivity (GLS) correlation metric to quantify filter-vector relationships; finds partition-based indexes beat HNSW at low selectivity and pgvector picks bad plans. [https://arxiv.org/abs/2602.11443]
- **RoarGraph: A Projected Bipartite Graph for Efficient Cross-Modal Approximate Nearest Neighbor Search** (VLDB 2024 (PVLDB 17(11))): Quantifies why cross-modal (OOD) queries break graph ANN — queries spatially deviate from base data and their kNNs are mutually distant — and fixes it with a query-distribution-guided bipartite graph (up to 3.56x faster at 90% recall); establishes the template of diagnosing a distribution-mismatch pathology then reshaping graph edges to match it. [https://arxiv.org/abs/2408.08933]
- **Down with the Hierarchy: The 'H' in HNSW Stands for "Hubs"** (ECIR 2026 (arXiv 2412.01940)): Shows on 13 datasets (1M-100M) that HNSW's hierarchy adds nothing in high dimensions because hub-node 'highways' emerge naturally, so entry-point machinery matters far less than assumed; a direct empirical challenge to any contribution premised on adaptive entry-point selection driving recall. [https://arxiv.org/abs/2412.01940]
- **Query-aware Routing for Filtered Approximate Nearest Neighbors Search** (arXiv (cs.DB), June 2026): A lightweight learned router that, per filtered query, predicts recall/QPS of multiple candidate filtered-ANN methods from an offline benchmark table and picks the best method+parameters; routes across whole methods rather than inside a graph, but occupies the 'learned per-query configuration for filtered ANN' slot. [https://arxiv.org/abs/2606.19898]
- **SpatCode: Rotary-based Unified Encoding Framework for Efficient Spatiotemporal Vector Retrieval** (WWW 2026 (arXiv 2601.09530)): Encodes time and location into rotary positional components of the embedding itself so spatiotemporal-plus-semantic retrieval happens in one similarity space, with incremental sliding-window updates and adaptive modality weighting, explicitly claiming to obviate multi-index and pre-filtering approaches. It sidesteps rather than solves filtered graph traversal, but directly attacks the same spatiotemporal-vector workload with a competing paradigm. [https://arxiv.org/abs/2601.09530]
- **Milvus 2.6.4: Hybrid Spatial and Vector Search (native GEOMETRY field + R-Tree index)** (Milvus production release, blog Mar 2026): Production vector DB now ships a native GEOMETRY column with R-Tree indexing and GEOS exact refinement, running spatial filter + vector similarity in one query via two-phase pre-filtering (R-Tree MBR prune, then ANN over surviving candidates). It is pipeline-level pre-filtering, not a co-designed index, and does not address recall loss of filtered graph traversal, but it changes the baseline landscape the proposal's 'Milvus fails' claim rests on. [https://milvus.io/blog/hybrid-spatial-and-vector-search-with-milvus-264.md]
- **Hybrid Indexes to Expedite Spatial-Visual Search (Alfarrarjeh & Shahabi)** (arXiv 2017 / ACM MM Thematic Workshops line of work): Co-designs R*-tree (spatial) with LSH (visual descriptors) into hybrid index structures for geo-tagged image search, evaluating spatial and visual dimensions in tandem on Flickr/Street View/GeoUGV. Pre-HNSW and LSH-based with no adaptivity, but it is direct prior art that spatial+visual hybrid indexes exist, so the proposal cannot claim to be first at index-level spatial-visual co-design. [https://arxiv.org/abs/1702.05200]
- **LIST: Learning to Index Spatio-Textual Data for Embedding-based Spatial Keyword Queries** (VLDB Journal 2024): Learned index for top-k spatial keyword queries where relevance combines embedding-based textual similarity with spatial distance, i.e., an index built specifically for spatial-plus-embedding retrieval.
