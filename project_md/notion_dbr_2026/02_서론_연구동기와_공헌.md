# 1. 서론 — 연구 동기와 공헌

## 왜 도시 감시 영상 검색이 필요한가

교차로 신호 운영, 사고 대응, 보행자·이륜차 등 교통약자 보호를 위해 감시 영상은 계속 축적된다. 실무 질의는 “오전 10시경 오토바이 두 대가 등장한 장면”처럼 자연어 의미와 시간·장소·센서 조건을 동시에 포함한다. 사람의 수작업 검토는 데이터 증가 속도를 감당하기 어렵다.

## 왜 전체 영상을 VLM에 직접 넣을 수 없는가

질의마다 모든 영상이나 프레임을 VLM에 제공하면 문맥 길이 한계를 넘고 GPU 비용이 폭증한다. 현실적인 파이프라인은 먼저 데이터베이스가 전체 코퍼스에서 상위 `k`개 클립·프레임·설명문을 검색하고, VLM은 이 제한된 검색 문맥만 보고 답한다.

따라서 병목은 단지 VLM 모델 성능이 아니다. 다음 데이터베이스 설계가 검색 품질과 비용을 함께 결정한다.

- 어떤 형태의 검색용 데이터를 저장하는가
- 메타데이터 조건을 검색 전·후 또는 탐색 중 언제 적용하는가
- 어휘·벡터·시각 신호를 어떻게 결합하는가
- 어떤 물리 색인을 사용하는가
- 전체 또는 조건별 어느 범위에 색인을 배포하는가

## 기존 평가가 가진 더 근본적인 문제

영상 벤치마크에서 질의, 필터 조건, 검색 문서, 정답 집합이 같은 사람 주석에서 파생될 수 있다. 이 경우 검색기가 영상을 잘 이해해서가 아니라 정답 정보가 조건이나 문서에 되풀이되어 높은 점수를 얻는다.

예를 들어 정답 클립만 통과하는 조건을 만들면 후보 집합이 곧 정답 집합이 된다. 정답 라벨 문구를 검색 문서에 다시 쓰면 BM25는 영상을 보지 않고도 질의와 같은 단어를 찾아 높은 순위를 매긴다. 이런 평가는 실제 운영 성능이 아니라 데이터 생성 과정의 중복을 측정한다.

## 연구 목표

1. 센서 기록, 영상 픽셀 기반 설명문, 사람 주석을 분리해 비순환 작업 부하를 확립한다.
2. 저장 방식·필터 계획·검색 신호·물리 색인·배포를 한 파이프라인에서 비교한다.
3. 검색 개선이 최종 VLM 답변으로 전달되는 조건과 한계를 검증한다.

## 논문의 세 가지 공헌

1. **평가 공헌**: 세 원천을 독립 분리하고 직접 누수를 자동 검사하는 비순환 평가 프로토콜을 수립한다. 정답 조건 및 라벨 재진술을 통제 주입해 점수 부풀림의 인과 효과를 정량화한다.
2. **데이터베이스 설계 공헌**: 검색용 데이터, 조건 적용, 검색 신호, 물리 색인, 배포를 품질·지연·저장·구축 비용으로 통합 비교한다.
3. **종단 간 공헌**: 데이터베이스 검색 개선과 최종 답변 사이에 증거 회수, VLM 인식, 질문·답변 편향이라는 전파 경계가 있음을 밝힌다.

## 반드시 지켜야 할 연구 범위

이 연구는 실시간 CCTV 스트리밍 시스템 전체를 구현한 연구가 아니다. 프레임 전수 캡션화, 비동기 임베딩 큐, delta 검색, 자동 hot/cold 전환, 동시 질의 부하는 실제 배치에 필요하지만 본 연구에서는 오프라인 설계 근거를 제공하는 범위에 머문다.

또한 “검색 품질이 좋아지면 답변도 반드시 좋아진다”, “필터는 항상 좋다/나쁘다”, “다중 이미지가 항상 최적이다”와 같은 무조건적 결론을 허용하지 않는다.
