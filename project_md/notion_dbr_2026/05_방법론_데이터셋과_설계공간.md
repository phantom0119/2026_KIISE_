# 4. 방법론 — 데이터셋과 설계 공간

## 전체 실험 흐름

![그림 1. 비순환 평가와 데이터베이스 설계 축을 포함한 전체 파이프라인](./assets/figure_01_pipeline.png)

1. 센서·메타데이터, 영상 픽셀·프레임, 사람 주석의 생성 경로를 분리한다.
2. 자연어 의미 조건과 메타데이터 조건을 결합한 질의를 만든다.
3. 비순환 감사를 먼저 통과시킨다(RQ1).
4. 검색용 데이터, 검색 계획, 검색 신호, 물리 색인과 배포를 비교한다(RQ2–RQ5).
5. 검색 결과를 VLM 입력으로 구성하고 최종 답변 변화를 확인한다(RQ6).

## 4.1 주 평가 데이터 구축

AI Hub 교차로 데이터의 세 채널은 다음과 같이 결합된다.

- 센서 카메라 채널: 시간·신호·교통량이 기록된 클립 `32,880개`
- 시각 카메라 채널: 영상 클립 `52,462개`
- 사람 주석과 연결된 시각 클립: `52,210개`
- 동일 교차로에서 촬영 시각 차이 `±120초` 이내의 가장 가까운 센서 클립을 연결해 확보한 시각 클립: `47,098개`
- 통제 설계 비교용 최종 코퍼스: 영상 설명문 `3,000개`

각 클립의 중간 이미지를 VLM에 넣어 교통량, 차종, 정차·주차 차량, 보행자, 도로, 날씨 중 화면에서 보이는 내용을 2–4문장으로 설명한다. 생성 모델에는 픽셀과 프롬프트만 제공하고 센서 기록과 사람 주석은 제공하지 않는다.

## 4.2 질의 85개 구축

메타데이터의 구체 조건값 `22개`와 의미 조건 `5종`을 교차해 후보 `110개`를 만든다.

| 메타데이터 범주 | 조건값 |
|---|---|
| 시간대 | morning, afternoon, evening |
| 황색 신호 | true, false |
| 보행 신호 | true, false |
| 센서 교통 밀도 | low, mid, high |
| 특정 시각 | 6, 7, 8, 9, 13, 14, 15, 16, 17, 18, 19, 20시 |

의미 조건은 주차 차량, 화면 내 개체 20개 이상, 버스 2대 이상, 정차 차량, 이륜차 2대 이상이다. 두 조건을 동시에 만족하는 양성 클립이 5개 이상인 조합 `85개`를 최종 질의로 확정한다.

주 평가 데이터는 설계 축을 통제 비교하고, 보완 데이터는 특정 메커니즘의 외부 타당성만 확인한다. 서로 다른 데이터셋의 절대 점수를 하나의 순위표로 합쳐서는 안 된다.

## 4.4 검색용 데이터 구성 — RQ2

| 구성 | 물질화 방식 | 클립당 벡터/색인 | 핵심 절충 |
|---|---|---:|---|
| 영상 설명문 | 클립을 요약한 텍스트 임베딩 | 1 | 저비용 기준선, 캡션 누락에 민감 |
| 대표 이미지 | 중간 또는 대표 프레임의 시각 임베딩 | 1 | 텍스트 없이 시각 신호 사용 |
| 이미지·설명문 결합 | 두 모달리티를 한 벡터로 융합 | 1 | 동일 벡터 예산의 중간 후보 |
| 다중 이미지 | 클립의 주요 프레임 여러 장을 각각 저장 | 최대 3 | 시간적·시각적 포괄성 증가, 저장·지연 증가 |
| 이중 색인 | 설명문 색인과 다중 이미지 색인을 별도 검색 후 RRF | 1+최대 3 | 모달리티 보존, 가장 높은 운영 비용 |

## 4.5 검색 계획 — RQ3

| 계획 | 처리 순서 | 장점 | 위험 |
|---|---|---|---|
| 벡터 단독 | 전체 코퍼스 의미 검색 | 의미상 관련 결과 보존 | 명시 조건 위반 가능 |
| 검색 전 조건 적용 | predicate → 부분집합 → 벡터 검색 | 필수 제약 보장, 후보 축소 | 관련 결과 조기 누락 |
| 검색 후 조건 적용 | 전체 벡터 top-200 → predicate 제거 | 넓은 의미 탐색 유지 | 필터 탈락이 많으면 top-k 부족 |
| 혼합 검색 | 사전 필터 → BM25·벡터 → RRF | 어휘·의미 결합 가능 | 약한 신호가 강한 순위를 희석 |

논문의 검색 계획 비교에서 혼합 검색은 텍스트 설명문에만 적용 가능하다. 따라서 유효한 데이터–계획 조합은 `1×4 + 4×3 = 16개`다.

## 4.6 검색 신호와 순위 융합 — RQ4

- 메타데이터 단독: 조건 통과 클립을 식별자 순으로 반환하는 결합도 기준선
- BM25: 질의와 설명문의 정확한 어휘 일치를 이용하는 sparse 검색
- 벡터: 임베딩 공간의 dense 의미 유사도를 이용
- BM25–벡터 RRF: 서로 다른 점수 대신 순위 역수를 합산

설명문 색인과 이미지 색인의 RRF인 “이중 색인”은 RQ2의 저장 구성이다. BM25와 벡터 신호를 결합하는 RRF는 RQ4의 검색 신호다. 같은 RRF라도 비교하려는 설계 축이 다르므로 혼동하면 안 된다.

## 4.7 물리 색인과 배포 — RQ5

| 색인 | 원리 | 대표 조절값 |
|---|---|---|
| Flat | 모든 벡터를 전수 비교하는 정확 검색 | 없음 |
| HNSW | 계층적 근접 그래프를 따라 탐색 | `M`, `efConstruction`, `efSearch` |
| IVF-Flat | 벡터를 군집화하고 일부 inverted list만 검색 | `nlist`, `nprobe` |
| IVF-PQ | IVF에 product quantization을 결합해 벡터 압축 | `m`, 비트 수, `nprobe` |

제출본 통합 격자는 Flat, HNSW `efSearch={64,256}`, IVF 계열 `nprobe={8,32}` 등 총 `7개` 물리 설정을 사용한다. 유효 데이터–계획 조합 `16개`와 결합해 `112개 구성`을 만든다.

배포 범위는 전체 데이터를 하나로 묶는 전역 색인과 자주 쓰는 조건별 부분집합만 별도로 색인하는 조건별 부분 색인을 핵심 비교로 삼는다. local/hot/cold는 운영 정책의 확장 개념이며, 제출본은 자동 동적 운영 전체를 구현한 것이 아니다.

## 4.8 최종 실험 규모를 읽는 법

- 구성 수: `112`
- 질의 수: `85`
- 정답 기준: `2`
- 품질 평가 계약: `112 × 85 × 2 = 19,040건`
- 지연 반복: 질의당 10회, 총 `95,200회`

`19,400건`은 제출 PDF에 없는 전치 오류다. 제출본의 정확한 값은 `19,040건`이다.
